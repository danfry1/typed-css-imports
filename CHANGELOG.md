# Changelog

## 0.2.0

- Go to definition, find references and rename between components and the module. The mapper returns a span map from each name in the generated types to its declaration: `styles.button` goes to `.button`, references from either file include the rule and every use, and renaming a name written as-is edits the CSS and the components. Sass names map through Sass's source map (`&-title`, `.tone-#{$t}`). Quoted and `localsConvention` names support definition and references but not rename.
- Generated types write names that are valid identifiers without quotes (`readonly button: string`). `typed-css-imports generate --check` reports files generated by 0.1.x as stale until they are regenerated.
- The source is TypeScript, compiled to `dist/`. `typed-css-imports/transform` now ships type declarations.
- New runtime dependencies `postcss-selector-parser` and `source-map-js`, both already installed as dependencies of postcss-modules and postcss.

## 0.1.0

First release.

- TypeScript 7.1 content mapper for `.module.css`, `.module.scss` and `.module.sass` imports: the default export is typed with exactly the names postcss-modules exports, including `localsConvention`.
- Sass modules are compiled with the project's `sass` or `sass-embedded`, with `loadPaths` and string `additionalData` options.
- CSS and Sass syntax errors are reported at their position in the module.
- `typed-css-imports generate` writes the same types to `.d.css.ts` / `.d.scss.ts` / `.d.sass.ts` files, with `--check` for stale files.
- Published manually, without npm provenance.
